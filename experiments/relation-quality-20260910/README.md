## 私人資料邊界

本分支不包含 PDF、私人教材檔名、OCR 文字、頁面圖片、概念端點標籤、參考答案、逐題判斷／理由、原始模型 request／response、思考內容、帳號憑證或服務金鑰。

完整私人材料與原始紀錄仍保留於使用者本機 workspace 的 `docs_local/relation-test`，不加入 Git／CI。本分支的結果可直接閱讀；僅靠遠端封存不能重新生成私人教材結果。這是刻意保留的資料邊界，不是已公開的可下載評測集。

## 如何參考與重現

1. 先讀 `REPORT.md`，區分固定概念對分類、自由圖譜來源支持及完成率。
2. 比較 `protocols/` 中實際的指示和輸出約束，尤其方向 ID 欄位順序及思考邊界。
3. 要以原私人資料重評，需有原始 `requests/`、`outputs/`、設定檔及 60 案例參考檔。將所需檔案放在 Git 以外的私人工作目錄，依各腳本的相對路徑安排。
4. 評分腳本的參考檔名已改為 `reference/reference-60.private.json`。原始私人檔名的對照只留本機，不在此公開。
5. 008／009 的準備腳本以 `RELATION_TEST_SOURCE_PDF` 指定私人 PDF，且依賴先前 007 的私人請求與既有設定。這些依賴沒有上傳；不要把此封存當成獨立、一鍵可執行的測試套件。
6. 原執行腳本是歷史快照，預設連接當地模型 API；閱讀快照不需啟動模型。**不要直接在封存分支執行推論或產生原始資料，也不要為驗證封存而啟動 Pod。**需要重跑時另建私人工作目錄，明確指定範圍與服務。

Python 腳本使用標準函式庫；部分推論腳本需 `jsonschema`，PDF render／prepare 需 `pymupdf`。文法資格測試涉及實驗當時的 XGrammar 0.2.3。模型服務版本記在 `experiment-index.json`，沒有新增產品 dependency。

## 012 的歷史範圍修正

012 原始準備／執行腳本規劃兩輪 24 次；執行途中使用者縮減為第一輪 12 次。實際在第 12 次輸出原子存檔後結束執行程序，第二輪 START 與結果均為零，沒有中斷第一輪請求或重跑失敗。

因此封存保留原始 `run.py`／`prepare.py` 的兩輪程式供稽核，但正式結果與 `score.py` **只含第一輪**。`score-original-two-rounds.py` 只作版本對照，不應拿來重算正式分數。綁定舊 PID 的一次性停止監看腳本未上傳，以免誤用。這些差異不代表測了兩輪，也不允許把缺席的第二輪當成失敗。

當時的 Pod 在結果下載並核對後已停止，未刪除。本分支不會部署或管理任何資源。
